# Бюджет токенов конвейера — сделанное и гипотезы к проверке

Рабочий файл: что уже внедрено, что предлагается и какие цифры ждать. Проверяется
следующими прогонами. Полный разбор с диаграммами — `docs/token-flow.html`.

## Как мерить (и как НЕ ошибиться)

Источник — транскрипты `~/.claude/projects/<проект>/*.jsonl` **плюс вложенные
`<session-id>/subagents/*.jsonl`**: субагенты пишутся отдельно, без них счёт занижен
на четверть.

**Обязательно дедуплицировать по `requestId`.** Транскрипт записывает одно обращение
к модели по два-три раза (одинаковый `requestId`, разные `uuid`). Суммирование по
записям завышает всё примерно вдвое — на этом я обжёгся 01.08.2026, первая версия
разбора называла $364 вместо $171.

Цены Opus за миллион токенов: вход $15 · выход $75 · запись кэша $18,75 · чтение $1,50.
При работе по подписке это мера расхода квоты, а не счёт.

## База для сравнения — два прогона 01.08.2026

| | Услуги B+ (7 карточек) | A2-4 (3 карточки) |
|---|---|---|
| Стоимость | $170,84 | $90,33 |
| Сессий (главных + разведчиков) | 23 + 18 | 10 + 3 |
| Обращений к модели | 766 | 360 |
| Прогрев / чтение / вывод | 33% / 52% / 15% | 28% / 58% / 15% |
| Сборка / разведка / гейты | 71% / 17% / 11% | 78% / 3% / 7% |
| Средний контекст хода в сборке | 97 тыс. | 110 тыс. |
| Пиковый контекст | 169 тыс. | 213 тыс. |
| Строк кода | 6 619 | 1 499 |
| Стоимость 1000 строк | $26 | $60 |

Состав контекста одной сборки (карточка «Перевыпуск пароля», 85 обращений,
59 тыс. на старте → 200 тыс. в конце):

| Что лежит в контексте | Размер | Доля финала |
|---|---|---|
| Стартовая обвязка CLI | ~35 тыс. | 17% |
| Промпт задачи | 4,6 тыс. | 2% |
| Результаты инструментов | 46 тыс. | 23% |
| — `Bash` (тесты, линтеры) | 23 тыс. | 11% |
| — `Read` (файлы целиком) | 21 тыс. | 11% |
| Ответы самой модели | 56 тыс. | 28% |
| Системные напоминания, повторные вставки | ~59 тыс. | 30% |

**Правило, из которого всё следует:** цена куска контекста = его размер × число
обращений, которые случатся ПОСЛЕ его появления. Поэтому 35 тыс. стартовой обвязки
(лежит с первого хода, множится на все 85) дороже 23 тыс. вывода тестов (появляется
в середине, множится на половину).

## Гипотезы к проверке — по убыванию ожидаемой отдачи

### 1. Обрезать вывод команд в сборке

`Bash` дал 23 тыс. токенов контекста за сессию, 56 вызовов. Вывод `pytest`, `mypy`,
`ruff` оседает целиком и перечитывается на каждом следующем ходу.

Правка в промпте `launchBuild`: требовать `pytest -q --tb=line`, `mypy … | tail -30`,
не печатать полные трейсбеки на зелёном прогоне.

**Ожидание:** 23 тыс. → ~8 тыс., то есть примерно −1,5 М чтения на сессию сборки.
Риск: агент не увидит деталь падения и запустит тест повторно с полным выводом —
получим лишний ход вместо экономии. Мерить надо `Bash`-токены И число вызовов вместе.

### 2. Батчинг проверок

`Bash` — самый частый инструмент (361 вызов за два прогона). Отдельные запуски `ruff`,
затем `mypy`, затем `pytest` — три обращения там, где хватило бы одного
`ruff && mypy && pytest`.

**Ожидание:** −10…15% обращений в сборке. Проверять по числу вызовов `Bash` на карточку.

### 3. Делегировать чтение больших файлов субагенту

В замеренной сборке `Read` принёс 21 тыс. токенов девятью вызовами — файлы падали в
главный контекст целиком. При этом механизм уже существует и иногда применяется сам:
два разведчика из 21 были вызваны с промптом «Read these files and report concisely»
(выжимка вместо файла).

Сделать правилом в промпте сборки: файл длиннее ~300 строк читает субагент.
**Важно:** это ровно та разведка, которую НЕ надо резать в гипотезе 5.

### 4. `--disallowedTools TodoWrite` в headless

57 обращений за два прогона на ведение списка задач, который в headless никто не читает.
~6% обращений. **Риск:** список — рабочая память агента на длинной карточке; без него
может вырасти число возвратов к уже сделанному. Проверять на одной карточке, не на всём
прогоне.

### 5. Не разведывать дважды внутри карточки

Разведчики за два прогона: 21 запуск, $31,17. Из них по назначению:

| Тип промпта | Запусков | Стоимость |
|---|---|---|
| `Explore the … domain` — разведка области | 12 | $17,16 |
| `Read these files and report concisely` — делегированное чтение | 2 | $4,54 |
| смешанные | 7 | $9,47 |

По фазам почти поровну: 10 в гейтах, 11 в сборках. Разведка домена в гейте и в сборке
одной карточки пересекается процентов на семьдесят.

Правильная формулировка — не «запретить», а **«передать результат»**: в промпт сборки
положить путь к `DevelopmentPlan.md` и отчёту разведки гейта, перезапуск разрешить
только по файлам, которых там нет.

**Риск, если просто запретить:** агент начнёт читать файлы сам, в главный контекст —
дороже, чем субагент (см. гипотезу 3).

### 6. Карта кода — одна на прогон

Один разведчик при старте прогона по объединённым `files[]` всех карточек →
`.grace-feature-dev/plan-<id>/CODEMAP.md`. В промпт карточки кладётся **путь**, не текст:
вложенное в промпт оплачивается на каждом ходу, а `Read` файла входит в контекст один раз.

Инвалидация дешёвая: карточка ушла в `ready` → разделы карты, покрывающие её `files[]`,
помечаются грязными → следующая карточка перечитывает только их. Механизм тот же, что
уже работает для контрактов (`result.contract` + `inheritContracts`). При вертикальной
нарезке пересечений `files[]` между карточками нет по построению, так что грязных
разделов будет мало.

**Ожидание, честно с обеих сторон:**

```
разведка сейчас (18 запусков)         −$28,7
одна карта + добор по грязным (4–5)   +$9
чтение карты в 7 карточках            +$7,5
                                      ──────
чистая экономия                        ≈$12   (7% прогона)
```

Меньше, чем кажется: карта не бесплатна, её тоже надо прочитать. Делать после гипотез 1–3.

### 7. Индекс, живущий между прогонами

A2-4 изучал ровно тот же репозиторий, что «Услуги B+» четырьмя часами раньше, с нуля.
Карта в `.grace/codemap/`, обновляемая по `git diff` от последней записанной ревизии:
изменились три файла — переразведать три файла. Тогда стоимость разведки перестаёт быть
функцией числа прогонов. Самая амбициозная и самая поздняя по очереди.

### 8. План-уровневый гейт решений (механизм уже есть, вход оборван)

`POST /api/plans` принимает `decisions[]`, они штампуются на карточки как `planDecisions`,
а `planDecisionsBlock()` вставляет в промпт «СОБЛЮДАЙ, НЕ переспрашивай». Во всех
6 планах на доске `decisions: 0` — потому что **у `gb run` нет флага для их передачи**.

Решения человек и так принимает на Ш7 при декомпозиции (в плане A2-4 это M-Q1, M-Q2,
M-Q3, утверждённые 01.08). Сегодня они доезжают до агента только как текст плана-файла.

Экономии токенов почти не даст (~$5 на прогон). Ценность другая: вопрос человеку стоит
часов простоя — в разборе 25–27.07 самый дорогой простой составил 8 часов на двух
вопросах о границах.

## Что мерить на следующих прогонах

1. **Доля прогрева** — должна упасть с 33% до ~25% (эффект урезанной обвязки).
2. **Средний и пиковый контекст хода в сборке** — растёт ли дальше при укрупнённых
   карточках; 213 тыс. уже близко к пределу.
3. **`Bash`-токены и число вызовов вместе** — по ним видно, работает ли обрезка вывода
   или просто прибавились ходы.
4. **Число разведчиков на карточку** — сейчас 2–3, целевое 0–1 после гипотез 5–6.
5. **Стоимость 1000 строк по типу работы** — backend с тестами дороже фронта ($60 против
   $26); нужен раздельный ориентир, иначе сравнения прогонов бессмысленны.
6. **Аварии** — три запуска сборки одной карточки A2-4 стоили $8,9 при 111 строках кода.
   Смерть по лимиту квоты пока дороже любой оптимизации нарезки.
