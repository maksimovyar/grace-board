# Промпт-заготовка: раскатка `.grace/`-конфига по проектам

> **Не запускать без явного «да».** Заготовка меняет чужие репозитории: пишет
> `.gitignore` и два файла в `.grace/`. Раскатывать по одному проекту за раз,
> глазами читая результат перед коммитом.
>
> Схема конфига — `docs/DESIGN-plan-skill-warden-config.md` §3.
> Эталон заполненного — `.grace/project.md` и `.grace/local.example.md` этого репозитория.

## Как пользоваться

1. Открыть сессию Claude Code **в целевом проекте**.
2. Скопировать туда всё, что ниже разделителя, подставив имя продукта.
3. Прочитать полученные файлы, убедиться в правилах 1–7 (см. ниже), закоммитить
   `.gitignore` + `.grace/project.md` + `.grace/local.example.md`.
   `.grace/local.md` не коммитится никогда.

---

Заведи в этом репозитории конфиг проекта для пайплайна grace-feature-dev.

**Шаг 0 (обязательно первым).** Добавь строку `.grace/local.md` в `.gitignore`
и убедись: `git check-ignore -v .grace/local.md` возвращает путь. Только после
этого создавай файлы — иначе адрес боевого стенда уедет в git первым же коммитом.

**Шаг 1.** Прочитай репозиторий: `README`, `CLAUDE.md`, `package.json` /
`pyproject.toml`, `.env.example`, конфиги CI, скрипты деплоя, схему БД.

**Шаг 2.** Создай `.grace/project.md` (коммитится) и `.grace/local.example.md`
(коммитится, пустой скелет) по схеме:

```yaml
---
product: <Имя продукта, а не имя папки>
repo_root: <где живёт приложение, если не корень>
stack: { lang: …, framework: …, db: …, pm: … }
commands:
  typecheck: …
  test: …
  build: …
  dev: …
  smoke: …
stand:
  is_production: true|false
deploy_policy: { pr: always|never, merge: manual|auto, deploy: off|after-merge|ask }
plan_approval: human|auto-if-no-questions
---

## Пути (относительно репозитория)
## env — только имена
## Расписания
## Константы
## Источники правды
```

`local.example.md` — те же ключи, что уедут в `local.md`: `stand.url`,
`stand.deploy_cmd`, `stand.rollback_cmd`, `notify {channel, chat}`, `board_url`,
плюс разделы `## Локальные пути вне репозитория` и `## Сервисы этой машины`.
Значения пустые — видно, что нужно заполнить на новой машине.

**Шаг 3 — правило разнесения фактов.** По каждому факту задай вопрос: «если
этот файл завтра окажется в публичном репо — что из него узнает посторонний?».
Узнаёт стек и структуру — оставляй в `project.md`. Узнаёт адрес боевого стенда,
id чата владельца, команду выкатки, абсолютный путь на машине — переноси в
`local.example.md` (и в `local.md` со значением, если можешь его установить).

**Правила составления (нарушать нельзя):**
1. Только то, чего агент не узнает из кода за 30 секунд. Находится grep'ом — не пишем.
2. Никаких указаний «как писать код» — это `CLAUDE.md`. Конфиг = справочник констант.
3. Каждая строка проверяема: путь существует, порт слушается, время в `HH:MM`.
4. Лимит 4000 символов на файл. Больше — значит попало лишнее.
5. Секретов нет нигде — только **имена** переменных и путь к `.env`.
6. Все разделы обязательны: пустой = «проверял, пусто», отсутствующий = «забыл».
7. Ничего не выдумывай. Чего не смог установить из кода — оставь строкой
   `TODO: <что именно неизвестно>`.

**Шаг 4.** Отдельным списком перечисли все `TODO:` — это ровно те вопросы,
которые иначе всплыли бы в рантайме первого прогона и остановили бы карточку.
Ничего не коммить: файлы читает и коммитит человек.
