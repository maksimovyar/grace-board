## Что уже готово — переиспользуем, не переписываем

- `resumeRun()` — resume с самой дальней достигнутой точки; проверено вручную 25.07,
  после возврата токенов `relaunch` продолжил сборку с места обрыва. **Работает, не трогаем.**
- `autoheal` в `syncFromPipeline()` — один повтор + `RECOVERY`-контекст из хвоста лога.
- `tailLog()` — дешёвое чтение последних 64 кБ лога. Классификатору хватит.
- WIP=1 и DAG-шедулер (`scheduleQueued`, `canDispatchNow`) — повтор обязан ходить через них.
- Шаг 4 этого же проекта даёт агента-стража и API `health/pause/resume/note`.

## Чего нет — пишем с нуля

- различения «ран умер по внешнему лимиту» и «ран умер из-за бага» — сейчас только liveness pid;
- состояния «пауза» на карточке; сегодня единственный исход — `blocked`;
- детекта массового события (несколько смертей в узком окне = один инцидент, не N поломок);
- пакетного возобновления прогона (делается вручную внешним watcher-скриптом).

## Модель данных (новые поля карточки)

Все поля аддитивные, дефолт = сегодняшнее поведение (инвариант forward-only).

| Поле | Тип | Смысл |
|---|---|---|
| `paused` | bool | карточка стоит, но не сломана; место в очереди сохраняется |
| `pausedReason` | `"quota" \| "manual" \| null` | почему стоим — это же показывает UI |
| `pausedUntil` | ISO \| null | когда истекает текущая ступень backoff |
| `quotaRetries` | int | счётчик повторов по лимиту; **не** трогает `autoHealCount` |
| `pausedIncident` | id \| null | связывает карточки одного массового события |

Колонка карточки при паузе **не меняется** — словарь `COLUMNS` остаётся закрытым.

## Rigor этапа

`grace` — в этапе есть машина состояний (жив → пауза → повтор → эскалация) и контур,
ломающий автономность прогона при ошибке. Все карточки этапа идут `--rigor grace`.

## Карточки — фаза «домен»

У этапа нет маршрутов UI, поэтому фаза «поверхности» вырождена: поверхностями
выступают эндпоинт и бейдж (Q4). Связки на каждой карточке:
`--req-link docs/plans/quota-resilience.md`, `--origin skill`, `--rigor grace`.

### Q1 · Доска · Quota · Классификатор смерти рана и флаг `paused`
- **Суть.** Перед авто-исцелением супервизор читает хвост лога умершего рана
  (`tailLog`) и сверяет со списком маркеров лимита. Совпало → `paused: true`,
  `pausedReason: "quota"`, `pausedUntil` = первая ступень backoff, событие в
  `DISPATCH_LOG`, вызов стража. Не совпало → сегодняшний путь `autoheal → blocked`.
- **НЕ входит.** Решение о повторе (это страж) · лестница backoff (→ Q3) · массовое
  событие (→ Q2) · бейдж в UI (→ Q4).
- **Приёмка.** (1) Мок-`claude` печатает `usage limit` и выходит ненулевым кодом →
  карточка в `paused`, **не** в `blocked`. (2) Мок падает с обычной ошибкой → прежний
  путь в `blocked`. (3) `autoHealCount` после quota-паузы не увеличился. (4) Одиночная
  карточка (`planId: null`) ведёт себя так же — режим не про прогоны.
- **Контракт.** Поля из раздела «Модель данных» + константа `QUOTA_MARKERS: string[]`
  (env-оверрайд `GRACE_QUOTA_MARKERS`). Событие
  `{event:"quota-pause", cardId, marker, attempt}`.
- **Файлы.** `server.js`
- **Зависимости.** —

### Q2 · Доска · Quota · Детект массового события и пакетная пауза
- **Суть.** ≥2 рана умерли в окне < 60 с → это глобальное событие (лимит подписки), а
  не N независимых поломок: пауза всех активных карточек **доски** одним решением,
  один `incidentId`, один вызов стража.
- **НЕ входит.** Индивидуальная классификация (Q1) · возобновление (Q3).
- **Приёмка.** Две карточки убиты в окне 30 с → обе в `paused` с общим `pausedIncident`;
  в `DISPATCH_LOG` **одно** событие `quota-incident`, а не два `blocked`.
- **Контракт.** `{event:"quota-incident", incidentId, cards:[id…], windowMs}`.
  Окно — константа `QUOTA_INCIDENT_WINDOW_MS = 60000`.
- **Файлы.** `server.js`
- **Зависимости.** Q1

### Q3 · Доска · Quota · Событие «истёк backoff» + счётчик повторов
- **Суть.** Тик проверяет `pausedUntil` и по истечении поднимает `quota-retry-due`
  (агент доску не опрашивает — DESIGN §2.1). Лестница 5/15/45 мин в `quotaRetries`;
  после третьей неудачи — `quota-escalate` одним уведомлением, карточка остаётся в
  `paused`. Событие не поднимается, если слот проекта занят (WIP=1).
- **НЕ входит.** Сам relaunch — его делает страж через существующий API.
- **Приёмка.** Карточка с `pausedUntil` в прошлом → ровно одно событие за тик;
  при занятом слоте проекта события нет; после 3-й неудачи — `quota-escalate`,
  колонка не изменилась.
- **Контракт.** `QUOTA_BACKOFF_MIN = [5, 15, 45]` (env-оверрайд);
  `{event:"quota-retry-due", cardId, attempt}`.
- **Файлы.** `server.js`
- **Зависимости.** Q1

## Карточки — фаза «поверхности»

### Q4 · Доска · Quota · Пакетное возобновление прогона + отметка в UI
- **Суть.** `POST /api/plans/:id/resume` снимает паузу со всех не-`ready` карточек
  плана и отдаёт их шедулеру по одной (WIP=1). В UI — бейдж «⏸ лимит» с подсказкой
  `pausedReason`/`pausedUntil` и кнопка «Возобновить прогон» на plan-rail.
- **НЕ входит.** Автовозобновление по расписанию (Q3 + страж) · пауза одиночной
  карточки кнопкой (есть в API шага 4, отдельного UI не делаем).
- **Приёмка.** Прогон из 3 карточек в `paused` → один POST → все сняты с паузы,
  стартовала ровно одна; бейдж виден и в колонке, и в открытой карточке; на токенах
  `public/styles.css`, без переопределения существующих классов.
- **Контракт.** `POST /api/plans/:id/resume → { resumed: [cardId…], dispatched: cardId|null }`.
- **Файлы.** `server.js`, `public/app.js`, `public/styles.css`
- **Зависимости.** Q3
- **Дизайн.** Источник — `## Дизайн` в `CLAUDE.md` (html · `public/`); бейдж рисуется
  по образцу существующих чипов карточки, отдельного макета не требует.

## Открытые вопросы

1. **После третьей неудачи повтора** — оставить в `paused` с одним уведомлением или
   всё же увести в `blocked`?
   *По умолчанию:* оставить в `paused` + уведомление (DESIGN §2.3 — «человека звать
   после 3 неудач», а не «сломать карточку»).
2. **Область массовой паузы** — вся доска или только проект, где умер ран?
   *По умолчанию:* вся доска (лимит подписки глобальный, аккаунт один).
3. **Список маркеров лимита** — константа в `server.js` или ключ в `.grace/local.md`?
   *По умолчанию:* константа + env-оверрайд: это свойство CLI, а не проекта.
