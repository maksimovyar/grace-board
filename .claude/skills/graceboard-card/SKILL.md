# graceboard-card — завести карточку на Доске

Доска (`grace-board`) — локальный kanban-диспетчер для пайплайна grace-feature-dev.
Zero-dep Node-сервер на `http://127.0.0.1:4317`, только 127.0.0.1, состояние в
`~/Projects/grace-board/data/board.json`.

Все операции — через готовый помощник **`~/.claude/bin/gb.mjs`** (Node ≥18), не собирай
JSON руками: описание может быть на десятки тысяч символов с кавычками/переносами.

## Порядок действий

1. **Проверь, что доска запущена:**
   ```bash
   node ~/.claude/bin/gb.mjs board --project <ПАПКА_ПРОЕКТА> | head
   ```
   Если «cannot reach board» — подними её: `cd ~/Projects/grace-board && node server.js &`
   (порт можно сменить через `GRACE_BOARD_PORT`).

2. **Создай карточку.** `--project` — имя папки проекта под `~/Projects` (или абсолютный путь
   внутри `~/Projects`), напр. `DocsInside2`, `kaizen-planer`. Длинное описание передавай
   через файл или stdin, не через `--desc`:
   ```bash
   # из файла
   node ~/.claude/bin/gb.mjs card --project DocsInside2 \
     --theme "Лайти · Stage 3 · Сервисный доступ Hermes (admin-scope JWT)" \
     --type backend --desc-file /path/to/task.md

   # из heredoc через stdin
   node ~/.claude/bin/gb.mjs card --project DocsInside2 \
     --theme "Доска · Stage 5 · Plan Run summary gate" --type screen --desc-stdin <<'EOF'
   Полный текст задачи…
   EOF
   ```
   Флаги: `--type` (см. ниже — единственная ручка исполнения), `--design-link URL`,
   `--req-link URL` (обе ложатся в `sources[]`).

## Тип карточки — единственная ручка исполнения (A5.1)

`--type backend|screen|integration|foundation|fix`. Без флага — `backend`.
Больше на карточке ручек нет: `--rigor`, `--model`, `--build-mode`, `--autonomy`,
`--requirements`, `--depends-on` СНЯТЫ (помощник останавливается с объяснением).
Строгость разметки, кто пишет код, режим сборки и порог предохранителя доска берёт
из своей таблицы типов в момент диспатча:

| type | что это | разметка | кодер | режим | порог A1.1 |
|---|---|---|---|---|---|
| `backend` | серверная логика, доменный слой | grace | обычный | inline | ×1.0 |
| `screen` | экран/UI-слайс | grace | **фронтендер (Opus + frontend-design)** | hybrid | ×0.8 |
| `integration` | стык с внешней системой | grace | обычный | inline | ×1.0 |
| `foundation` | каркас, схема, миграции | grace | обычный | inline | ×0.7 |
| `fix` | правка по конкретному провалу | **off** | обычный | inline | ×0.5 |

**Смешанная карточка — по доминирующей работе.** «Экран» = вертикальный слайс с UI,
включая мелкую серверную обвязку (эндпоинт, который он читает). Честные 50/50 фронт+бэк
— это ДВЕ карточки, связанные через `contract` (бэкенд публикует, экран получает готовым).

Зависимости (`dependsOn`) на карточке не задаются: их задаёт сборка прогона —
`gb run --stage ID:dep1,dep2` (скилл **graceboard-run**).

3. **Сверь длину.** Помощник печатает `description: sent N chars, stored M chars ✓/✗`.
   Если `✗ TRUNCATED` (exit 2) — описание превысило 50000 и хвост срезан МОЛЧА; сократи и пересоздай.

## Бриф карточки — обязателен, когда карточку заводит агент

`--origin human|skill|agent`. У `human` доска не требует ничего. У **`skill`/`agent`
она требует полный бриф и иначе ОТКАЖЕТ В ДИСПАТЧЕ** (`briefGaps` в `server.js`):

| Флаг | Что это |
|---|---|
| `--out-of-scope "…"` \| `--out-of-scope-file PATH` | что НЕ входит + адрес («→ этап C» / «не делаем») |
| `--acceptance "пункт"` (повторяемый) | DoD проверяемыми пунктами; из них собирается приёмка прогона |
| `--source "источник"` (повторяемый) | источники с приоритетом и пометкой устаревшего |
| `--contract "…"` \| `--contract-file PATH` \| `--contract TBD` | модели/поля/эндпоинты дословно; `TBD` = проектируется в этой карточке |
| `--file path/to/x.ts` (повторяемый) | реальные пути репозитория: по ним доска держит пересекающиеся карточки в очереди |

**Коды выхода:** `0` — ок · `2` — описание срезано · `3` — бриф неполон (помощник
печатает, чего не хватает). Ненулевой код чини сразу, а не на preflight.

## Соглашения (не нарушать — это и есть смысл скилла)

- **Тема всегда `<Продукт> · <Этап/эпик> · <Суть>`.** Пример:
  `Лайти · Stage 3 · Сервисный доступ Hermes (admin-scope JWT)`.
- **Имя продукта, а не имя папки.** Маппинг: `kaizen-planer` → **Лайти**, `grace-board` → **Доска**;
  Погода, Виноградарь, English Teacher, Otherside watcher, DocsInside — как есть.
  Путь проекта в UI мелкий, по нему продукт не опознать. Особенно обязательно, когда одна
  работа заводится в несколько репо (CI в 5 приложениях) — без префикса карточки в списке неразличимы.
- **Называй правильно СРАЗУ.** Тему/поля можно править только пока карточка в **Backlog** и не
  задиспатчена; после диспатча PATCH отдаёт **409** (`only a Backlog task can be edited`,
  `grace-board/server.js` — хендлер PATCH `/api/tasks/:id`).
- **Полный текст задачи — в `description`** (лимит 50000, `MAX_DESC`). В колонке он обрезан до
  2 строк, в открытой карточке виден целиком. Раньше лимит был 2000 и лишнее срезалось молча.
- **Поля `requirements` больше нет** (A5.3): полный текст задачи — только в `description`.
- **Ссылки — это источники.** `--design-link` / `--req-link` доска складывает в `sources[]`
  рядом с остальными, в порядке приоритета; отдельных полей под них на карточке нет.
- **Проект виден на карточке чипом** — в теме всё равно ставь имя продукта: чип говорит,
  КУДА поедет работа, тема — ЧТО это за работа.

## Прогон (Plan Run) из нескольких карточек
Если нужно собрать несколько карточек в один прогон с зависимостями — это скилл
**graceboard-run** (сначала карточки этим скиллом, потом сборка плана там).
